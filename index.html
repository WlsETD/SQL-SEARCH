一間渡假村，四個部門要答案

澄海渡假村在恆春半島的海邊（虛構），有四種房型與 SPA、浮潛、海灘燒烤等設施。以前靠紙本和 Excel，聖誕節同一間房賣了兩次，取消單也被算進營收。

改用關聯式資料庫後，旅客、客房、訂單和設施各一張表、以外來鍵相連，每個部門都能用 SQL 自己查。卡片上的編號會打開對應的查詢。

設計時定下的六條規則

  1. 房型資訊只存一次

    名稱、人數與定價只放在 room_type，客房只記 type_id。調價改一列，不會前後不一致。

    room.type_id → room_type.type_id

  2. 訂單保存成交價

    price_per_night 是訂房當下的價格，和定價分開，折扣與聖誕加價都留得住。

    price_per_night * 晚數 AS 房費

  3. 取消不刪除

    取消的訂單改狀態保留紀錄，統計營收和查空房時都要記得排除。

    WHERE status <> '已取消'

  4. 住宿區間是 [入住, 退房)

    退房那天下一位就能入住，判斷兩筆訂單重疊要用 < 與 >，不能用 BETWEEN。

    b.check_in < '退房日' AND b.check_out > '入住日'

  5. 設施消費掛在訂單下

    facility_order 參照訂單而不是旅客，才知道是哪一次住宿花的錢，也能和房費一起結帳。

    facility_order.booking_id → booking.booking_id

  6. NULL 代表非會員

    member_level 可以是 NULL，查詢時要用 IS NULL 或 COALESCE 處理，不能只寫 <>。

    COALESCE(member_level, '非會員')
