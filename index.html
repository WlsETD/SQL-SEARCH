澄海渡假村
訂房與設施資料庫

一間虛構的海濱渡假村，用關聯式資料庫管理客房、訂單與設施預約。所有 SQL 都在你的瀏覽器裡以 SQLite 執行，可以直接修改、執行、看結果或錯誤訊息。

1

案例背景

這個資料庫給誰用？要解決什麼問題？

澄海渡假村位於恆春半島海邊（虛構），共有 12 間客房，分成標準雙人房、豪華海景房、家庭四人房與私人泳池別墅四種房型，另外提供 SPA、浮潛、立槳、海灘燒烤與親子課程等設施。

過去訂房靠紙本登記加上 Excel，常出包：同一間房在聖誕節被重複賣出、取消的訂單被算進營收、經理不知道哪間房一直空著、行銷也說不出誰是高消費旅客。因此改用關聯式資料庫，把「旅客、客房、訂單、設施」拆成彼此關聯的資料表，讓每個部門都能用 SQL 找到答案。

設計時的商業規則

  1. 房型資訊只存一次名稱、人數、定價放在 room_type，每間 room 只記 type_id，調價只要改一列（正規化，避免重複與不一致）。
  2. 訂單保存「成交價」booking.price_per_night 是訂房當下的價格，與定價 base_price 分開；有 VIP 折扣、聖誕加價，日後調價也不影響舊訂單。
  3. 取消不刪除取消的訂單改 status = '已取消' 保留紀錄，所以統計營收、查空房時都要記得排除。
  4. 住宿區間是 [入住, 退房)退房日當天可以讓下一位旅客入住，兩筆訂單「重疊」的判斷要用 < 與 >。
  5. 設施使用掛在訂單下facility_order 參照 booking 而非 guest，才知道是哪一次住宿的消費，也能跟房費一起結帳。
  6. NULL 代表非會員guest.member_level 允許 NULL；查詢時要用 IS NULL 或 COALESCE 處理。
